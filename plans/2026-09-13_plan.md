# Durus (دروس) — Master Plan

Date: 2026-09-13 · Status: APPROVED (scope) — code phases pending user go-ahead

---

## 1. Product Summary

Private-lessons management for one teacher or a small team:

- Teacher manages **students, subjects, weekly schedule, attendance, variable
  monthly fees, tests/results, notes, monthly reports**.
- Parents follow up via a **link (PIN portal)** — responsive web, any device.
- Arabic only, RTL.
- **First-launch wizard** decides single-teacher vs multi-teacher mode; in
  multi mode there is a **manager** with full admin control.

## 3. Roles & permissions

| Capability | Manager | Teacher | Parent |
|---|---|---|---|
| Manage teachers (invite / create / disable) | ✅ | — | — |
| All students (any teacher's) | ✅ | own only | own child only |
| Subjects CRUD | ✅ | ✅ | — |
| Schedule / attendance | ✅ all | own students | view child |
| Fees ledger | ✅ all | own students | view status |
| Tests / notes / reports | ✅ | own students | view own child |
| Announcements to parents | ✅ | ✅ | receive |
| Admin settings / backups | ✅ | — | — |

Multi-teacher scoping is enforced in Postgres (RLS on `assigned_teacher`), not
in the UI.

## 4. Data Model (draft)

```
users            id, email (teacher/manager), password_hash, role,
                 is_manager, school_name (multi mode), created_at
parents          id, name, phone, pin_hash, student_ids (link portal)
students         id, name, grade, birth_year, subjects[], default_location
                 (teacher_home|student_home), assigned_teacher_id, parent_id
subjects         id, name, grade, notes            (full CRUD)
recurring_slots  id, student_id, subject_id, day_of_week, start_time,
                 end_time, location, teacher_id
sessions         id, slot_id, date, attendance (present|absent|rescheduled),
                 session_note, recorded_by
fees             id, student_id, month (YYYY-MM), amount (variable),
                 due_date, status (unpaid|partial|paid), paid_amount,
                 payment_history (JSON or payments table)
payments         id, fee_id, amount, date, method (cash|transfer|other), note
tests            id, student_id, subject_id, type (monthly|midterm|final),
                 date, score, max_score, comment
notes            id, student_id, author_id, body, created_at, linked_session_id?
reports          id, student_id, month, summary (attendance %, fees status,
                 latest scores, notes), generated_at
announcements    id, author_id, body, sent_at, audience (all|parents)
notifications    id, recipient_type (parent|teacher), recipient_id, title,
                 body, icon, read_at, pushed_at (reserved for FCM), created_at
invitations      id, manager_id, code, status, expires_at, created_at
```

## 5. Supabase strategy

- ONE Supabase project (free tier), `supabase/` migration files in-repo.
- Tables per §4 with **RLS enabled on every table**:
  - Teacher: `assigned_teacher = auth.uid()`
  - Manager: `is_manager = true` (bypasses teacher scoping)
  - Parent: `student.parent_id` matches their link token / user id
- Realtime: attendance updates + announcements pushed to parent portal.
- Storage: optional — photos of homework/exams (Phase 8).
- Auth: teacher/manager use Supabase Auth (email+password). Parents: v1 PIN
  links (random token, stored hashed) — no Supabase Auth account required.

## 6. Screen map

### Teacher/Manager (Android app — Flutter)
1. Onboarding: Arabic-first welcome + **single vs multi wizard** (one-time)
2. Login (teacher/manager)
3. Home dashboard: today's sessions, pending fees, recent absences
4. Students: list → detail (profile, schedule, attendance history, fees
   ledger, tests, notes)
5. Subjects: CRUD screen
6. Schedule: weekly calendar; add/edit recurring slots
7. Attendance: per-session present/absent/rescheduled + session note
8. Fees: per-student ledger; mark paid/partial; overdue list ("who owes")
9. Tests: CRUD (monthly/midterm/final; score)
10. Reports: auto monthly summary per student; share to parent
11. Announcements: broadcast to parents
12. Teacher management (manager only): invitations + create-teacher
13. Settings: profile, branding, backup, (multi) manage teachers

### Parent portal (responsive web — Flutter web, same codebase)
- Open link → enter PIN → see child only:
  - Upcoming sessions, last attendance
  - Attendance history (month view + %)
  - Fee status (due/paid)
  - Notes, test results, monthly report
- Super-simple UX; works on any phone/tablet/desktop; no account.

### Admin dashboard (responsive web)
- Full-control tables/panels: students, teachers, fees across all, reports,
  announcements, settings, backups. (Manager role only.)
